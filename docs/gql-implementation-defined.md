# What zu leaves to itself

ISO/IEC 39075:2024 Clause 24.5.2 asks a conforming implementation to state its answer to two lists of items, and this file is zu's answer to both of them. Generated by `zu conformance --implementation-defined`. Do not edit by hand: the answers live in `crates/zu-cli/src/impdef.rs` and the items come out of the two published artifacts in `crates/zu-common/artifacts`, mechanically, so an item cannot be reworded here to suit an answer.

The first list is implementation-defined: an answer that must be the same every time and must be published, which is what this file does. The second is implementation-dependent: an answer the standard asks neither to be stable nor to be published. zu publishes those too, as behaviour observed today and not as a promise, because a reader who knows what an engine does can write a query that does not depend on it.

## Implementation-defined (117 items)

### IA001

Whether the declared type of a regular result of a successful outcome of a GQL-request is exposed to the GQL-client.

No. A reply carries the column names and the rows, and every value on the wire carries its own kind, so a client reading one knows what it is holding without being told what the column was declared to hold. The shell's `prepare` op reports the parameter names a statement will read, which is the one place a declared type would be useful and the one place it is not yet published.

### IA002

The extent to which further GQL-status objects are chained.

Nothing is chained. A reply carries one GQL-status object, and a statement that could have raised two reports the first one that stopped it.

### IA003

The result of any operation other than a normalize function or a normalized predicate on an unnormalized character string.

The operation reads the code points that were written. zu normalizes nothing on its own, so a string that arrived unnormalized compares, joins, folds and is measured as the sequence it is, and NORMALIZE is the only thing in the language that changes it.

### IA004

The rules for determining the actual value of an approximate numeric type from its apparent value.

IEEE 754 binary64, round to nearest with ties to even, which is what the hardware underneath does.

### IA005

Whether rounding or truncating occurs when least significant digits are lost on assignment.

Truncation toward zero, and no condition is raised for it. `CAST(1.9 AS INTEGER)` is 1 and `CAST(-1.9 AS INTEGER)` is -1.

### IA006

The choice of value selected when there is more than one approximation for a numeric type that conforms to the criteria for each supported type of numeric value.

There is never a choice to make. zu has one approximate type, binary64, so a value has one approximation and not several.

### IA007

Which supported numeric values other than exact numeric types also have approximations.

None. The numeric types are a 64 bit signed integer and a binary64 float, and the float is the approximation rather than a type that has one.

### IA010

The boundaries within which the normal rules of arithmetic apply.

Integer arithmetic is exact from -9223372036854775808 to 9223372036854775807 and an answer outside that raises `22003` rather than wrapping. Float arithmetic is IEEE 754 binary64 throughout, and an answer that left the range a double holds raises `22003` as well rather than travelling as an infinity, since a value that travels is one a later comparison answers false about and a statement that got one would have been told nothing.

### IA011

Whether rounding or truncating is used on division with an approximate mathematical result.

Rounding, to nearest with ties to even, a float division being the hardware's. An integer division truncates toward zero instead, `7/2` being 3, because two exact operands keep the answer exact.

### IA012

Whether a GQL Flagger flags implementation-defined features.

zu has no GQL Flagger, so nothing is flagged.

### IA013

Whether the General Rules of Evaluation of a selective path pattern are terminated if an exception condition is raised.

Yes. The first condition raised ends the statement, and the paths the selector had not reached are not walked.

### IA014

Whether an exception condition is raised when the declared type of NULL cannot be determined contextually.

No. A null whose type nothing around it settles is a null of the open dynamic union type and travels as one.

### IA015

Whether to pad character strings for comparison, or not.

No padding. `'ab '` and `'ab'` are two strings and compare unequal.

### IA016

Whether to treat byte string differing only in right-most X'00' bytes as equal, or not.

No. A byte string is compared by its bytes, so two that differ in a trailing X'00' differ.

### IA017

Whether or not an exception condition is raised or an arbitrary value is chosen when multiple assignments to a graph element property are specified.

An exception condition is raised. Assigning twice to the same property of one element in one SET is refused by name, because the element holds one value and the clause has not said which of the two it meant. Two SET clauses in a row are not that case and stay last wins.

### IA019

Whether ‹bidirectional control character›s are permitted in string literals.

Yes. A string literal holds whatever code points were written between its quotes, and zu reads none of them as controls.

### IA020

Whether characters of the Unicode General Category class “Co” are permitted to be contained in the representative form of an identifier.

No. An identifier is built from the Unicode general category classes ISO 21.3 names, and Co is not one of them, so a private use character neither starts nor continues a name.

### IA021

Whether an exception condition is raised, or truncation or rounding occurs, when an assignment of some number would result in a loss of its least significant digits.

Truncation, toward zero, with no condition raised. The one assignment that raises instead is a string too long for the type it is going into, which raises `22001` when what would be cut off is not spaces and reports `01004` when it is.

### IA023

The character (code) interpreted as newline.

U+000A. A U+000D immediately before one is part of the same break rather than a break of its own, so source text written on either kind of machine reports the same line numbers.

### IA025

The effect that additional values resulting from the support of Feature GA01, “IEEE 754 floating point operations” have on the processing of a GQL-request.

An infinity or a NaN that arrives as data travels through arithmetic the way IEEE 754 says it should. What the numeric library will not do is answer one where the standard names a condition, so a logarithm of nought raises `2201E` rather than answering minus infinity, and an argument that was already infinite is left alone, the conditions being about a statement that asked for a number nobody has.

### IA026

Whether a GQL-implementation supports leap seconds or discontinuities in calendars, and the consequences of such support for temporal arithmetic.

Neither is supported. A day is 86400 seconds and the calendar is proleptic Gregorian throughout, so temporal arithmetic is exact and has no discontinuity in it to reason about.

### ID001

The object (principal) that represents a user within a GQL-implementation.

zu has no principal. A session is a process holding a file open, and who may open it is the file system's answer rather than the engine's.

### ID002

The association between a principal and its home schema and home graph.

There is no principal, so there is no association. A session's home schema is the root, `/`, and its home graph is the graph in the file it opened.

### ID003

The set of privileges identified by an authorization identifier.

There is no authorization identifier and there are no privileges.

### ID004

The value types of inner elements of constructed values when no concrete value is specified.

The open dynamic union type. An empty list is a list of it, which is what lets it be joined to a list of anything.

### ID005

The declared type of an ‹elements function›.

A list of the union of node and edge. ELEMENTS answers a path's nodes and edges in the order the walk took them, so both kinds are in the one list.

### ID006

The default transaction characteristics.

Read write. A statement outside a transaction runs in one of its own, which commits when it completes and rolls back when it raises.

### ID016

The translations of condition texts.

There are none. A condition's text is the standard's English wording out of the conditions artifact, and the message beside it is zu's own English.

### ID017

The map of diagnostic information, if provided.

A failure carries `gqlstatus`, `condition`, `severity` and `message` always, the graph and schema it was raised in, the subject kind and subject where a name was at fault, and the line, column, byte offset and an excerpt of the source text where the position is known.

### ID022

The default collation.

Code point order over the string's Unicode scalar values, with no locale in it, so `'B'` sorts before `'a'`. An engine whose order changed with the machine's locale would answer one ORDER BY two ways on two machines holding one file.

### ID023

The preferred name of a string type, for each supported kind of string type.

STRING for the character string type and BYTES for the byte string type. There is no fixed length or maximum length string type to name.

### ID028

The effective binary precision of each supported integer type.

64 bits, signed, two's complement. It is the one integer type, and the narrower spellings the standard names are read as it.

### ID034

The effective decimal precision of each decimal type.

zu declares none. DECIMAL is accepted as a type name and a value under it is held as binary64, so there is no decimal type with a precision of its own to publish.

### ID037

The effective binary precision and scale of each supported approximate numeric type.

53 bits of significand and an exponent from -1022 to 1023, which is IEEE 754 binary64 and is the one approximate type.

### ID048

The default time zone displacement.

UTC, `+00:00`.

### ID049

The default session parameters.

None. A session starts with no parameters and the ones a statement reads are the ones the caller passed with it.

### ID057

The exact numeric type with scale 0 (zero) of list element ordinal positions.

The 64 bit signed integer, which is the one exact numeric type.

### ID058

The exact numeric type with scale 0 (zero) of list element position offsets.

The 64 bit signed integer, for the same reason.

### ID059

The exact numeric declared type of results of the COUNT function.

The 64 bit signed integer. A count that reached the top of it would raise `22003` rather than wrap, which no file this engine can open is large enough to do.

### ID061

The declared type of SESSION_USER.

zu has no SESSION_USER, having no principal for it to name.

### ID062

The exact numeric declared type of a non-negative integer specification.

The 64 bit signed integer.

### ID063

The numeric declared type of the result of a dyadic arithmetic operator when either operand is approximate numeric.

The binary64 float. An exact operand beside an approximate one is widened before the kernel sees them, so `2.0 * 3` is 6.0.

### ID064

The numeric declared type of the result of a dyadic arithmetic operator when both operands are exact numeric.

The 64 bit signed integer, unwidened.

### ID065

The precision of the result of addition and subtraction of exact numeric types.

64 bits, the same as the operands. An answer that does not fit raises `22003` rather than growing the type.

### ID066

The precision of the result of multiplication of exact numeric types.

64 bits, on the same terms.

### ID067

The precision and scale of the result of division of exact numeric types.

64 bits and scale 0, the answer truncated toward zero. A divisor of nought raises `22012`.

### ID068

The exact numeric declared type of results length expressions.

The 64 bit signed integer. CHAR_LENGTH and OCTET_LENGTH both answer it.

### ID069

The numeric declared types of results of trigonometric functions, general logarithm functions, natural logarithms, exponential functions, and power functions.

The binary64 float, whatever arrived. The answer of a root, a logarithm or an angle is irrational for all but a handful of arguments, and a type that changed with the value would be a type nothing could be planned against.

### ID070

The declared type of the result of a cardinality expression.

The 64 bit signed integer.

### ID074

The precision of an exact numeric result of a numeric value expression.

64 bits.

### ID075

The precision of an approximate numeric result of a numeric value expression.

53 bits of significand, binary64 throughout.

### ID076

The declared type of results of the ELEMENT_ID function.

STRING.

### ID079

The declared type of an approximate numeric literal.

The binary64 float, under any of the spellings the standard gives one: an exponent, a `D` suffix, an `F` suffix or an `M` suffix all read as it.

### ID085

The nullable declared type of NULL if its declared type cannot be determined contextually.

The open dynamic union type, nullable.

### ID086

The default graph pattern match mode.

DIFFERENT EDGES. Under it a pattern that named no path mode walks a TRAIL, and no one edge answers two of the edge patterns of the list.

### ID089

The use of GRAPH or PROPERTY GRAPH in the preferred name of graph types and graph reference value types.

GRAPH.

### ID090

The use of NODE or VERTEX in the preferred name of node types, node reference value types, and their base types.

NODE.

### ID091

The use of EDGE or RELATIONSHIP in the preferred name of edge types, edge reference value types, and their base types.

EDGE.

### ID095

The exact numeric declared types of the results of the SUM function.

The 64 bit signed integer, and a total that does not fit it raises `22003` rather than wrapping.

### ID096

The exact numeric declared types of the results of the AVG function.

zu declares none. An average of exact numbers is a binary64 float here, since the average of two integers is not in general an integer and an exact answer would have to be rounded to be given.

### ID097

The approximate numeric declared types of the results of the SUM and AVG functions.

The binary64 float.

### ID098

The approximate numeric declared types of the results of the STDDEV_POP and STDDEV_SAMP functions.

The binary64 float.

### ID099

The approximate numeric declared types of the results of binary set functions.

The binary64 float.

### IE001

The object, resource, or value identified by a URI or a URL.

zu resolves none. A graph is named by a path in the catalog or is the graph in the file the session opened, and there is no URI anywhere in the language it reads.

### IE002

The levels of transaction isolation, their interactions, their granularity of application and the Format and Syntax Rules for ‹implementation-defined access mode› used to select them.

One level, and no implementation-defined access mode to select it with. A transaction reads the snapshot it opened on and a write publishes at commit, so a read never sees half a statement and two sessions on one file each see their own snapshot.

### IE003

The UAX31-R1-1 profile if used.

None. The identifier syntax is ISO 21.3's general category classes rather than a UAX31 profile.

### IE004

Relaxations of the assumption of serializable transactional behavior, if any.

None declared.

### IE005

The treatment of language that does not conform to the Formats and Syntax Rules.

It is refused with `42001` and a position: the line, the column, the byte offset and an excerpt of the source text. Nothing outside the grammar is guessed at, extended or read as something near it.

### IE006

Additional restrictions, requirements, and conditions imposed on mixed-mode transactions.

None. A catalog statement and a data statement mix in one transaction, which is GP18, and two graphs mix in one, which is GT03, so `25G02` and `25G04` are unreachable here.

### IE007

The conditions raised when the requirements on mixed-mode transactions are violated.

None, there being no requirement to violate.

### IE008

Additional conditions for which a completion condition warning (01000) is raised.

Two. `01000` reports a VALUE or EXISTS query that reads a name from the query around it, since that one is answered once per row rather than once and the warning names what to lift out. `01004` reports a cast to a string type that cut trailing spaces off, the cut being lossless in that case and a refusal in every other.

### IE009

Additional informational conditions raised.

None.

### IE010

The subclasses providing information of a non-cautionary nature when the completion condition is successful completion.

`00001 omitted result`, which a statement that completed without returning a table reports.

### IL001

The minimum and maximum cardinalities of label sets, for each kind of graph element.

A node carries at least one label and at most 64, its labels being the bits of one word. An edge carries exactly one, the type its rel table is named by.

### IL002

The maximum cardinalities of property sets, for each kind of graph element.

4096 for a node and 4096 for an edge, a table being that many columns wide.

### IL003

The minimum and maximum cardinalities of key label sets, for each kind of graph element.

None to 63, for both kinds. A key label set is one short of the label set that has to contain it, so the pattern around it has room in the word.

### IL009

The minimum length of a string resulting from string concatenation of strings of variable-length string types, for each supported string type.

The sum of the two operands' lengths. A join is the code points of the left followed by the code points of the right and nothing is dropped, so there is no length below which the answer is guaranteed and above which it is not.

### IL010

The maximum number of digits permitted in an unsigned integer literal.

19, the digits of 9223372036854775807. A literal with more raises `42001` at the position of the literal rather than being read modulo anything.

### IL011

The maximum precision and scale of numbers of numeric types, for each supported kind of number.

64 bits for the integer type and 53 bits of significand for the float. There is no decimal type with a scale of its own, so there is no maximum scale to publish.

### IL013

The maximum lengths of string values of string types, for each supported string type.

zu declares none. A string is bounded by what the store can hold rather than by a number the language publishes, so `22001` is raised by a cast to a narrower string type and not by a limit on the type itself.

### IL015

The maximum cardinality of constructed values, for each supported constructed value type.

zu declares none, which is why `22G10` is unreachable here. A path or a list a query builds is bounded by the row it is built for rather than by a number worth publishing, and a limit invented so a condition could be provoked would be a limit nobody wanted.

### IL018

The maximum value of the upper bound of a general qualifier.

zu declares none. `{n,m}` takes any m that fits the integer type, and a quantifier with no ceiling at all is refused with that as the reason rather than being bounded silently.

### IL020

The maximum depth of nesting of GQL-directories.

zu declares none. A catalog path nests as deep as it is written.

### IL023

The minimum and maximum values of the exponent for an approximate numeric type.

-1022 and 1023, IEEE 754 binary64's.

### IL024

The maximum value of fractional seconds precision for a temporal instant or a temporal duration.

9 digits, a nanosecond, which is what the temporal lanes hold.

### IS001

The implicit ordering of NULLs.

A null sorts last under an ascending key and first under a descending one, so it behaves as though it were larger than every value. NULLS FIRST and NULLS LAST are read where they are written and they move the nulls to that end of the result rather than to an end of the order, so a descending key with NULLS FIRST still leads with its nulls.

### IV001

The character repertoire of GQL source text.

Unicode, read as UTF-8. Source text that is not valid UTF-8 is refused before it is lexed.

### IV002

The result of an inequality comparison between operands that are essentially comparable values when not otherwise specified.

The order zu answers with is total and it is one order for the whole engine, read by `<`, by ORDER BY, by DISTINCT and by GROUP BY alike. Within a type it is the type's own order: numbers by value across the exact and the approximate types, strings by code point, byte strings by byte, temporals of one kind by instant, booleans false before true.

### IV003

The choice of the normal form of each supported kind of GQL-object type with a defined normal form.

There is one form for each and it is the one the type printer writes, so there is no second spelling for a normal form to be chosen from. A graph type prints as its node types and its edge types in catalog order.

### IV008

The choice of the normal form of each supported kind of value type with a defined normal form.

The form the type printer writes: `INT64`, `FLOAT64`, `STRING`, `BOOL`, `LIST<T>` and the temporal names, with `NOT NULL` where a type is not nullable.

### IV010

The result of a comparison between two operands that are universally comparable values.

Two values of different types compare by a fixed order over the types themselves: null, boolean, number, string, byte string, temporal, node, edge, list, record, path, graph, binding table. It is stated rather than left to whatever order the enum happened to be declared in, because a documented choice can be relied on and a declaration order cannot, and it is why `22G04` is unreachable here.

### IV011

The dynamic union type chosen as the dynamic property value type.

The union of what a property column can hold: boolean, the 64 bit integer, the binary64 float, string, byte string, date, local time, local datetime, zoned time, zoned datetime, duration, and a list of any one of those.

### IV012

The set of component types of the open dynamic union type.

Everything IV011 names, and node, edge, path, record, graph and binding table besides, which is every type a value can have here.

### IV014

The set of value types that includes at least one supertype of every static value type supported by the GQL-implementation.

`ANY`, the single type every value type is under.

### IV015

The valid syntactic representation of an authorization identifier.

There is none, zu having no authorization identifier.

### IV016

The description of any additional text provided about conditions.

The message beside a condition is written for the person reading it, in English, and says what was asked and what was wrong with it. Where the fault is in source text it carries the line, the column, the byte offset and an excerpt, and where it is a name it carries the kind of thing the name was and the name. The condition text beside the message is the standard's and never zu's.

### IV023

The set of characters included in truncating whitespace.

The space, U+0020, and nothing else. TRIM with no character named takes spaces off both ends, and a wider set is written out with BTRIM, LTRIM or RTRIM.

### IW001

The mechanism for instructing a GQL-client to create and destroy GQL-sessions to GQL-servers, and to submit GQL-requests to them.

A session is a process. `zu shell` opens one on a file and reads a request per line as a JSON frame, and the session ends when the input does. The C ABI is the same session opened in process rather than over a pipe, and there is no server and no network protocol in either.

### IW002

The mechanism for creating and destroying authorization identifiers, and their mapping to principals.

There is none.

### IW003

The mechanism for determining when the last request has been received.

End of input on the session's pipe, or the caller closing the connection through the C ABI.

### IW004

The alternative mechanism for starting and terminating transactions.

There is none beyond START TRANSACTION, COMMIT and ROLLBACK. A statement written outside one runs in a transaction of its own.

### IW005

The mechanism by which termination success or failure statuses are made available to the GQL-agent or administrator.

The status object on the last reply, and the process's exit status.

### IW006

The mechanism for determining the dictionary of GQL-request parameters.

The `params` object of the query frame. The shell's `prepare` op reports the names a statement will read, so a caller can tell what to fill without running it.

### IW007

The manner in which GQL-status objects are presented to a GQL-client.

As a `gqlstatus` field on every reply, and on a failure as a `failure` object beside it holding the code, the standard's condition text, the severity, zu's message and the diagnostics ID017 lists.

### IW010

The manner in which external procedures are provided.

zu provides none.

### IW011

The mechanism for determining the reference value type of an element variable declared by a graph pattern.

It is the union of the element types the pattern could bind, worked out from the labels the pattern wrote and the tables of the graph that carry them. A pattern that named no label binds the union of every table the graph holds.

### IW012

The mechanism for determining the reference value type of an element variable declared by insert node pattern.

It is the node type of the table the written label names, which the INSERT creates when no table is named by that label and the graph type is open.

### IW014

The mechanism used to determine if two character strings are visually confusable with each other.

zu applies none, which is why `42004` is unreachable here. Two identifiers that render alike are two identifiers: the Latin a and the Cyrillic a are different characters in every encoding and this engine reads them as different names.

### IW015

The manner, if it so chooses, in which a GQL-implementation automatically creates and populates a GQL-directory.

zu creates the root directory and nothing else automatically.

### IW016

The manner, if it so chooses, in which a GQL-implementation automatically populates a GQL-schema upon its creation.

A new schema holds nothing until a statement puts something in it.

### IW017

The manner in which the result of the concatenation of non-normalized character strings is determined.

The code points of the left operand followed by the code points of the right, with no normalization before the join or after it. A join of two strings that were each normalized is not itself guaranteed normalized, and NORMALIZE is how a query that needs it says so.

### IW018

The manner in which lax casts (and supporting type tests) are generated and included in the syntax transforms for the dynamic generation of strict casts.

zu generates none. A cast is written or it is not, and a value that will not convert raises rather than being coerced quietly. The one widening that happens without being written is an exact operand beside an approximate one, which is ID063 rather than a lax cast.

### IW019

The mechanism for determining a common supertype of a set of value types of the same primary static base type.

The narrowest type of the set that every other is under, and where there is none, the base type they share. The answer is nullable when any member of the set is.

### IW021

The mechanism for determining a permutation of all value types of a set of value types that adheres to type precedence rules.

The order of the type table, which is IV010's order over the primary types and is fixed rather than derived per query.

### IW022

The mechanism for determining if the null value is not actually going to be assigned to a site.

zu makes no such determination ahead of the assignment. A site holds a validity bit and an assignment of null clears it, which is the same write a REMOVE is.

### IW023

The mechanism for determining the canonical name form of a ‹delimited identifier› or ‹non-delimited identifier›.

A delimited identifier is the characters between its quotes, a doubled quote standing for one. A non-delimited identifier is the characters as written. Neither is case folded, so `n` and `N` are two names, and a name written one way in one statement has to be written the same way in the next.

### IW025

The mechanism for determining which and how many catalog-modifying procedures are under transaction control, and which catalog-modifying procedures can be contained in a single transaction.

All of them, and any number of them in one transaction. A catalog change is written under the same savepoint a data change is, so the two roll back together and neither can be left behind by the other.

## Implementation-dependent (20 items)

### UA001

The interaction between multiple GQL-environments within the constraints of GQL-transaction semantics.

There is one environment per process and two do not interact. Two sessions on one file each read their own snapshot, and what one commits the other sees on its next transaction rather than inside the one it is in.

### UA002

Whether or not diagnostic information pertaining to more than one condition is made available.

No. One reply carries one status object, which is IA002's answer read from the other side.

### UA004

Whether or not that exception condition is actually raised when the evaluation of an inessential part of an expression or search condition would cause an exception to be raised.

It is not raised. A part of an expression that was never evaluated raises nothing: the second operand of an OR the first operand settled is not evaluated, nor is a CASE branch whose condition did not hold, nor is an argument of COALESCE past the first that was not null. This is deliberate rather than incidental, and the compiler asks which functions can raise when it decides what to put behind a guard.

### UA005

Which path bindings are retained in an any paths search if the number of candidates exceeds the required number.

The ones the walk reached first, which follows the order of the storage's adjacency lists.

### UA006

Which additional path bindings are actually probed to establish whether they might also raise an exception when the GQL-implementation has terminated the evaluation of a selective path pattern.

None. The walk stops when it has what the selector asked for and probes nothing further.

### UA007

Whether or not a rollback is forced when a GQL-transaction becomes blocked, cannot complete without causing semantic inconsistency, or the resources required to continue its execution become unavailable.

A statement that is interrupted or runs out of resources rolls back what it had written, the savepoint being the unit that is undone.

### US001

The sequence of records in an unordered binding table.

The order the plan produced them in, which is scan order through the storage for a match and insertion order for a table a statement wrote. It is the same order twice for one plan on one file, and it is not a promise: a plan change moves it and nothing warns.

### US005

The order of path bindings that have the same number of edges.

The order the walk reached them, which follows the adjacency lists.

### US006

The relative ordering of peers in a sort.

The order they arrived in. The sort is stable, ties being broken on the row's position, so a second ORDER BY over an already sorted table keeps what the first one decided.

### US007

The relative ordering of items in a sort whose comparison is Unknown.

There is no such pair. The order is total, which is what supporting GA04 means, so an ORDER BY never has an Unknown to place.

### US008

The actual order of expression evaluation.

Left to right, with the two exceptions UA004 names: a conjunction stops at the operand that settles it, and only the branch of a CASE that holds is evaluated.

### US009

The point in time at which the request timestamp is set.

When the statement begins, before it is planned. Every reading of the clock inside one statement answers the same instant, so two columns of one row cannot disagree about what time it is.

### UV001

The value of an object identifier.

A node's is its table and its row within that table. An edge's is its rel table and the ordinal the load order gave it. Both are stable for as long as the file is not rewritten.

### UV003

The ‹value expression› whose evaluation raises the exception condition: “data exception — invalid value type (22G12)”.

The first one the evaluator reaches that holds a value of the wrong type, evaluation being left to right.

### UV004

The value value returned by an evaluation of the ELEMENT_ID function.

A string naming the table and the row within it. It is unique within the file and it says nothing about a graph in another file, so a client that stored one and reopened a rewritten file has a string and not a handle.

### UV005

The physical representation of an instance of a data type.

The physical types the columnar store holds: a boolean is a bit in a word, an integer is two's complement of its width, a float is its IEEE 754 bits, a string is bytes with offsets into a buffer, a date is days from the epoch, a time is nanoseconds, a duration is months and nanoseconds held apart, and a list is offsets over its element column.

### UV007

The declared type of a site that contains an intermediate result.

The type the compiler worked out for the expression that fills it, which is the narrowest type every value it can hold is under.

### UV009

Which arbitrary value is chosen when multiple assignments to a graph element property are specified.

None is chosen. zu raises instead, which is the other answer IA017 allows, so this item has no observable value here.

### UV014

The start datetime used for converting intervals to scalars for subtraction purposes.

There is none. A duration holds months and nanoseconds apart rather than as one scalar, and a subtraction of two dates answers a duration in days, so no interval is ever converted against an anchor datetime.

### UW001

The mechanism for determining which exception condition is to be returned as the primary GQL-status object of an execution outcome from a set of raised exception conditions.

The first exception raised, since a statement stops at it. There is never a set of raised conditions to choose a primary from.
